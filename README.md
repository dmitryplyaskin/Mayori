# Mayori

Mayori превращает [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) из coding harness в основу для продолжительных ролевых игр. Первый релиз — устанавливаемый DSH bundle: он заменяет deployment persona и добавляет конфигурируемые правила ведущего через штатный реестр system prompt.

## Что уже работает

- роль ведущего вместо coding persona;
- собственная RPG-боковая панель с логотипом `Mayori Engine`, без списка coding-проектов и сессий;
- импорт Character Card v2/v3 из JSON и PNG (`chara` / `ccv3`), галерея, история чатов и запуск чата с выбранным персонажем;
- защита агентности персонажа игрока;
- Trajectory с просмотром входа выбранного запроса: без заменённых сообщений, с доступом к полному журналу;
- последовательность мира, хронологии и мотиваций NPC;
- разделение внутриигрового и внеигрового разговора;
- инструмент `rollDice`: вложенные запросы, произвольные числовые кости, арифметика и журнал выпавших граней;
- файлы кампании как будущий источник канонического состояния;
- честное отношение к случайности: модель не изображает бросок без реального rules/dice provider.

## Установка

Поддерживаемая версия DSH: **0.2.1-alpha.1**. Для запуска через `pnpm dlx` указывайте её явно: локальный checkout DSH этой командой не используется.

Mayori устанавливается в отдельный именованный профиль. Не добавляйте bundle в
штатный профиль `web`: browser plugin регистрирует branding и галерею на уровне
всего профиля.

Сначала создайте отдельный профиль из встроенной Web-композиции и установите Mayori:

```sh
pnpm dlx @deepseek-ai/dsh@0.2.1-alpha.1 --profile mayori --from-default-profile web --dump-config
pnpm dlx @deepseek-ai/dsh@0.2.1-alpha.1 plugin --profile mayori add github:dmitryplyaskin/Mayori
```

Если профиль уже был создан без `--from-default-profile web`, он может содержать только `@deepseek-ai/dsh-base`.
В таком случае добавьте встроенный Web bundle перед Mayori в
`$DSH_HOME/profiles/mayori/package.json`:

```json
{
  "dsh": {
    "profile": {
      "bundles": [
        "@deepseek-ai/dsh-base",
        "@deepseek-ai/dsh-web-app",
        "dsh-mayori"
      ]
    }
  }
}
```

Чтобы интерфейс Mayori работал на отдельном от обычного Web origin, назначьте ему порт в
`$DSH_HOME/profiles/mayori/cordis.patch.yml`:

```yaml
- id: credentials
  config:
    path: !!js dshHomePath('profiles/mayori/.credentials.yaml')
- id: webserver
  config:
    host: !!js ctx.webStartup.host ?? '127.0.0.1'
    port: 3081
```

Так ключи, сохранённые из интерфейса Mayori, также не изменяют общее
`$DSH_HOME/.credentials.yaml`.

Проверьте композицию и запускайте именно именованный профиль:

```sh
pnpm dlx @deepseek-ai/dsh@0.2.1-alpha.1 --profile mayori --dump-config
pnpm dlx @deepseek-ai/dsh@0.2.1-alpha.1 --profile mayori
```

Обычный `dsh web` продолжит использовать чистый профиль `web` без Mayori.

Для воспроизводимой установки закрепляйте commit:

```sh
dsh plugin --profile mayori add github:dmitryplyaskin/Mayori#<commit-sha>
```

Если Mayori раньше была установлена в основной профиль, удалите её штатной
командой: `dsh plugin --profile web remove dsh-mayori`.

Пакет поставляет готовые Host и browser JavaScript artifacts и не запускает `prepare` при установке из GitHub.

## Настройка

Системная инструкция Mayori содержит роль ведущего, игровые правила и выбранную карточку с персоной игрока. Bundle отключает технический контекст DSH и coding-инструменты. Один preset `mayori` сохраняет общие инструкции. В **Настройки → Mayori → Плагины** независимо включаются кости, проверки и чтение подробностей. Выключенные инструменты не попадают в контекст модели; выбор сохраняется для новых и существующих чатов. [Руководство по плагинам](docs/plugins.md).

Bundle добавляет строку `mayori-director`. Её можно заменить в `$DSH_HOME/profiles/mayori/cordis.patch.yml`:

```yaml
- id: mayori-director
  config:
    narratorName: Хранитель
    languagePolicy: Всегда отвечай по-русски.
    campaignStyle: Медленный мистический хоррор с упором на расследование.
    additionalInstructions: Не предлагай больше трёх явных зацепок в одной сцене.
```

Профильный patch применяется после bundle, поэтому пользовательские значения побеждают. Пропущенные поля получают defaults из схемы плагина.

## Главная страница

Бренд `Mayori Engine` открывает главную Mayori через штатную навигацию, без создания пустой сессии. Кнопка `New Session` убрана; новую историю можно начать кнопкой `Играть` на карточке персонажа. Вкладка `Главная` встречает приветствием, показывает пять последних неархивных чатов и пять недавно загруженных карточек. Под каждым разделом есть переход в полную историю или каталог. Чат открывается в прежней сессии; `Играть` на карточке начинает новую историю. Без выбранного чата и в безымянном пустом черновике главная заменяет прежний экран ввода. Именованный чат с пустым приветствием сохраняет обычное поле сообщения.

## Галерея персонажей

Пункт `Персонажи` находится в основной навигации боковой панели и доступен без активной сессии. Это штатная кнопка DSH (`sidebar.panellist`), открывающая галерею в основной области приложения: справа находятся импорт, поиск, сортировка и фильтры, слева — грид карточек. По умолчанию показываются пять карточек в ряд; можно выбрать 3, 5 или 7. Выбор сохраняется в этом браузере, на узком экране сетка уменьшает число колонок. Пагинация ограничивает страницу 20, 40 или 60 карточками (по умолчанию 20); этот выбор также сохраняется. При изменении поиска, фильтров, сортировки или лимита открывается первая страница. Если карточки удалены, номер страницы ограничивается последней доступной. Кнопка `Играть` создаёт отдельную новую сессию в текущей или последней кампании, привязывает к ней карточку, называет чат именем персонажа и открывает его. Если кампаний ещё нет, Host автоматически создаёт `$DSH_HOME/mayori/campaigns/default`, регистрирует каталог как Workspace и открывает чат внутри него — выбирать папку вручную не требуется. Корневой каталог можно заменить полем `campaignsPath` в конфигурации `mayori-director`. При нажатии `Играть` чат сразу содержит первое сообщение из `first_mes`, без обращения к модели. Карточки каталога не показывают выбор «Начало истории» и preview приветствия. Запуск с карточки использует основное приветствие. В окне информации («Изменить») можно выбрать альтернативное начало, посмотреть приветствие с подставленными именами и нажать «Играть»; это работает и при пустом основном приветствии. В самом чате альтернативы также переключаются до первого хода игрока. Пустое основное приветствие позволяет начать без готового сообщения. Выбранное начало сохраняется в истории, доступно модели и не меняется при обновлении карточки. Альтернативы, которые вы не выбирали, в контекст модели не передаются. В уже существующие чаты приветствия автоматически не вставляются. `Изменить` открывает информационную модалку. Галерея принимает несколько файлов за один раз:

- Character Card v2/v3 в `.json`;
- PNG-карточки v2 с блоком `chara`;
- PNG-карточки v3 с блоком `ccv3`; если в PNG есть оба блока, используется v3.

Рядом находится вкладка `История чатов`: единый список сохранённых чатов всех кампаний на этом Host, от новых к старым, без группировки по директориям. Каждая строка содержит аватар, имя персонажа, сокращённое последнее сообщение и дату. Название чата также показано, если оно отличается от имени персонажа. Без аватара используется первая буква имени. Данные берутся из сохранённого выбора персонажа и журнала сессии, включая закрытые чаты; просмотр списка не активирует сессию и не вызывает модель. Поиск работает по названию и ID чата; дата помогает различать чаты с одним персонажем. История также разбита на страницы по 20, 40 или 60 чатов. Нажатие открывает прежнюю сессию, а `Обновить` повторно загружает каталог. История включает обычные ветки и именованные чаты, созданные через `Играть`, даже до первого сообщения; пустые черновики и служебные чаты субагентов скрыты. Источник — постоянный каталог сессий DSH, поэтому история доступна после перезагрузки браузера и перезапуска Host. Поиск по тексту сообщений пока не добавлен. Кнопка `В архив` после подтверждения убирает чат из обычной истории, сохраняя переписку. Включите `Архив` и нажмите `Восстановить`, чтобы вернуть его. Архив хранится на Host и переживает перезапуски. Выполняющий работу чат DSH не архивирует: сначала дождитесь завершения или остановите работу в самом чате. При архивировании текущего чата DSH снимает его выбор и может переключить основную область; архив доступен при повторном открытии истории. Это обратимое архивирование, а не окончательное стирание данных.

Файл ограничен 16 МБ. Host сохраняет карточки в `$DSH_HOME/mayori/characters`, поэтому каталог не зависит от браузера, порта или Web origin. JSON карточки и исходные PNG лежат в файловом хранилище; повторный импорт того же содержимого обновляет существующую запись, неизвестные поля сохраняются без изменений. Путь можно заменить полем `charactersPath` в конфигурации `mayori-director`. Сейчас галерея не импортирует `.charx`.

Снимок стандартных полей выбранного персонажа хранится отдельно в `$DSH_HOME/mayori/campaigns/selections/<hash-session-id>.json`. Он неизменяемый: для другого персонажа создаётся новый чат. Host восстанавливает scoped model context на ожидаемом событии `agent/created`, прежде чем DSH примет первый ввод; изменения или удаление исходной карточки не переписывают уже начатый чат. Форк чата получает собственную копию выбора. Неизвестные поля и `extensions` в модельный контекст не попадают. Штатная система DSH записывает фактически переданный модели контекст в session log. Нестандартные типы событий и патчи ядра не требуются.

В чате с первым сообщением и альтернативами появляются кнопки `‹ 1 / N ›`. До первого хода игрока они циклически переключают начало истории. Выбор сохраняется в журнале и восстанавливается после перезагрузки; модель получает только выбранное начало. После отправки сообщения приветствие блокируется. Пустое альтернативное приветствие также можно выбрать.

### Персоны игрока

Вкладка `Персоны` позволяет создать несколько персонажей игрока: указать имя, описание, необязательную подпись и аватар PNG/JPEG/WebP до 2 МБ. Сохраните персону и нажмите `Использовать по умолчанию`, чтобы новые чаты начинались с ней. `Играть в этом чате` сохраняет введённые изменения и закрепляет персону за открытым чатом. До первого хода эта операция также обновляет приветствие; после начала игры предыдущая переписка сохраняется.

Имя заменяет `{{user}}`, описание заменяет `{{persona}}` и передаётся модели как описание персонажа игрока. Подпись помогает различать персоны, аватар показывается в списке и справа от каждого сообщения игрока; они не передаются модели. Аватар персонажа из PNG-карточки находится слева от каждого его сообщения, включая приветствие. Нажатие открывает изображение целиком; окно закрывается кнопкой, Escape или нажатием за его пределами. Если изображения нет, показывается первая буква имени. Без выбранной персоны используется имя `Игрок`. Каталог хранится на Host в `$DSH_HOME/mayori/personas`; путь настраивается через `personasPath`. Каждый чат хранит свою копию: редактирование или удаление персоны из каталога не меняет уже созданные чаты.

В панели разговора сначала идёт `Чат`, затем `Trajectory`. Контекст карточки и описание игрока находятся в отдельном разделе системного сообщения после инструкций ведущего, перед приветствием и вводом игрока, включая провайдеры с обновлением prompt внутри истории. В Trajectory раскрытие SYSTEM показывает этот раздел в фактически сохранённом запросе. Старые запросы сохраняют исходный порядок; новый порядок применяется со следующего обращения к модели после перезапуска Host.

### Базовые шаблоны SillyTavern

Подстановка работает в приветствиях, их предварительном просмотре в окне информации и стандартных модельных полях карточки. Имена макросов нечувствительны к регистру, допускают пробелы вокруг имени. Поддерживаются:

- `{{user}}`, `{{char}}`, `{{persona}}`, `{{charIfNotGroup}}`, `{{group}}`, `{{groupNotMuted}}`, `{{notChar}}`;
- `{{description}}` / `{{charDesc}}`, `{{personality}}` / `{{charPersonality}}`, `{{scenario}}`, `{{mesExamples}}` / `{{charExamples}}` / `{{charExamplesRaw}}`;
- `{{charPrompt}}`, `{{charJailbreak}}`, `{{charVersion}}`, `{{charCreator}}`;
- `{{newline}}`, `{{space}}`, `{{trim}}`, `{{noop}}`, комментарии `{{// …}}` и старые обозначения `<USER>` / `<BOT>`;
- `{{date}}`, `{{time}}`, `{{isodate}}`, `{{isotime}}`, `{{weekday}}`: UTC-время создания чата, сохранённое для повторяемой подстановки;
- `{{original}}` и `{{input}}`: пустая строка, поскольку в карточке нет исходного prompt override или активного draft input.

Текст карточки не является шаблоном DSH: `{{cwd}}`, `{{model}}`, неизвестные и некорректные конструкции остаются данными. STscript, переменные SillyTavern, случайный выбор и броски не исполняются. Это базовый набор совместимых подстановок; исходная карточка сохраняется без изменений.

### Миграция с прежней версии

Переустановите локальный пакет через `pnpm dlx @deepseek-ai/dsh@0.2.1-alpha.1 plugin --profile mayori add C:\pet_projects\Mayori` и полностью перезапустите DSH. В профильном `cordis.patch.yml` проверьте переопределения `system-prompt`: поле `persona` заменено на `personaPrefix` и `personaSuffix`. Профильные overrides применяются последними и могут перекрыть новый preset; для игры выбирайте `mayori`. Browser вкладку перезагрузите после перезапуска.

Карточки галереи сохраняются без изменений. Старые сессии с обязательными событиями `mayori/character-selected`, созданные пропатченным DSH, не конвертируются автоматически: штатный DSH может отказаться читать такие журналы. Не удаляйте и не редактируйте их вручную; перед отдельной конвертацией сохраните резервную копию всего DSH home. Обычные сессии без этих событий мигрирует сам DSH.

## Броски кубиков

Переключатель «Кости» в **Настройки → Mayori → Плагины** добавляет native инструмент `rollDice`. Любое положительное число граней в пределах лимита допустимо без регистрации. Поддерживаются арифметика, `kh`/`kl`, взрывы `!`, перебросы `r`/`ro`, сравнения, подсчёт успехов, ссылки на результаты текущего batch и ленивые условия.

`rolls` сохраняет форму дерева. Обычный ответ содержит только `rollId`, `values` и непустой `errors` при ошибках. Листья — числа/boolean, ошибки отдельных полей дают null; независимые поля продолжают вычисляться. Полная запись версии 3 сохраняет грани, ветки и ссылки в журнале и карточке, включая форк и восстановление. Модель читает её через `getRollDetails({ "rollIds": ["id-из-ответа"] })`, без новых бросков. Старые результаты остаются читаемыми. Сохранённый пул внутри batch можно исследовать через `count`, `countFaces` и `face`. `details: true` сохранён для совместимости; подробности прежнего броска читайте только по его `rollId`.

Формат запросов, примеры условий, семантика модификаторов и Config описаны в [руководстве по кубикам](docs/dice.md).

Инструмент `resolveCheck` отдельно возвращает натуральную грань, модификатор, итог, сложность, явный исход (включая крит), условный урон и настроенное последствие. Правила и формулы фиксируются до броска и сохраняются в журнале. Профили, примеры и Config описаны в [руководстве по проверкам](docs/rules.md).

Игровые возможности независимы и переключаются на странице Mayori в штатных настройках. Проверки автоматически используют Dice provider без дополнительного `rollDice`, если свободные броски выключены. Настройки применяются также к существующим чатам. Публичные entries `dsh-mayori/dice`, `/rules`, `/roll-history` доступны для собственных композиций; `/mechanics` сохранён для совместимости. См. [настройку плагинов](docs/plugins.md) и [чтение подробностей](docs/roll-history.md).

## Статус

Mayori находится на ранней стадии. Текущий bundle задаёт модельный опыт, заменяет Web sidebar на расширяемую RPG-навигацию и предоставляет настоящие числовые броски и проверки с явными исходами. Отдельные сервисы состояния кампании, игровых rulesets и полноценный RPG-интерфейс ещё не реализованы.
