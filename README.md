# Mayori

Mayori превращает [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) из coding harness в основу для продолжительных ролевых игр. Устанавливаемый DSH bundle добавляет библиотеку пользовательских пресетов игры и подключает выбранные инструкции через штатный реестр system prompt.

## Что уже работает

- роль ведущего вместо coding persona;
- отдельная вкладка **Пресеты**: создание, редактирование, дублирование и выбор инструкций для новых или текущего чата;
- собственная RPG-боковая панель с логотипом `Mayori Engine`, без списка coding-проектов и сессий;
- импорт Character Card v2/v3 из JSON и PNG (`chara` / `ccv3`), галерея, история чатов и запуск чата с выбранным персонажем;
- защита агентности персонажа игрока;
- Trajectory с просмотром входа выбранного запроса: без заменённых сообщений, с доступом к полному журналу;
- редактирование реплик игрока и персонажа, повтор ответа и переключение сохранённых веток; [руководство](docs/messages.md);
- последовательность мира, хронологии и мотиваций NPC;
- разделение внутриигрового и внеигрового разговора;
- инструмент `rollDice`: вложенные запросы, произвольные числовые кости, арифметика и журнал выпавших граней;
- настраиваемое [сжатие длинной истории](docs/compaction.md): собственная инструкция, порог заполнения контекста и сохранение последних сообщений;
- файлы кампании как будущий источник канонического состояния;
- честное отношение к случайности: модель не изображает бросок без реального rules/dice provider.

## Установка

Нужны Node.js **^22.19.0 или >=24** и pnpm. Поддерживаемая версия DSH —
**0.2.1-alpha.2**. Клонировать Mayori, создавать папки и редактировать
конфигурационные файлы для обычной установки не требуется.

При первой установке выполните две команды:

```sh
pnpm dlx @deepseek-ai/dsh@0.2.1-alpha.2 --profile mayori --from-default-profile web --dump-config
pnpm dlx @deepseek-ai/dsh@0.2.1-alpha.2 plugin --profile mayori add github:dmitryplyaskin/Mayori
```

Первая создаёт профиль из встроенной Web-композиции и выводит конфигурацию;
вторая устанавливает Mayori с GitHub. Если профиль `mayori` уже существует,
первую команду повторять не нужно. Для обновления повторите вторую команду.

Каждый последующий запуск — одна команда:

```sh
pnpm dlx @deepseek-ai/dsh@0.2.1-alpha.2 --profile mayori
```

Откроется интерфейс на `http://127.0.0.1:3081`. Доступ к модели настраивается
через интерфейс. Другой порт можно выбрать параметром `--port`.

Bundle автоматически выбирает отдельный каталог данных `~/.dsh-mayori`:
на Windows это `C:\Users\<текущий пользователь>\.dsh-mayori`, на Linux/macOS —
`$HOME/.dsh-mayori`. Путь вычисляется по домашней папке пользователя.
Журналы чатов, реестр Workspace и кэш их проекций, вложения, управляемые
credentials и игровые каталоги используют этот корень. Папки создаются
соответствующими хранилищами по мере использования. Задавать `DSH_HOME`
в терминале не нужно; обычный coding DSH использует свои прежние хранилища.

Сам профиль и установленный пакет остаются в стандартном
`$DSH_HOME/profiles/mayori`; его настройки сохраняются штатным DSH отдельно
от профиля `web`. Служебные данные установки и общие технические кэши DSH
не являются историей Mayori. Отдельный порт разделяет браузерные настройки.

Не добавляйте Mayori в профиль `web`: branding и игровые contributions
действуют на весь профиль. Если она раньше была установлена туда, удалите
её штатной командой:

```sh
pnpm dlx @deepseek-ai/dsh@0.2.1-alpha.2 plugin --profile web remove dsh-mayori
```

При переходе с общего хранилища старые чаты и карточки автоматически не
перемещаются и не удаляются. Новые чаты сохраняются в отдельном каталоге.
Перед обновлением сделайте резервную копию данных Mayori и профиля.
Пакет поставляет готовые JavaScript artifacts и не запускает `prepare`.

Для воспроизводимой установки вместо ветки закрепите commit в адресе
`github:dmitryplyaskin/Mayori#<commit-sha>`.

## Настройка

Во вкладке **Пресеты** создавайте свои инструкции для ролевой игры и выбирайте их для новых или текущего чата. Начальный редактируемый пресет **Mayori** содержит прежние правила ведущего. Изменение или удаление пресета в библиотеке сохраняет копии инструкций в уже созданных чатах; применение обновляет инструкции для следующих ходов. [Руководство по пресетам](docs/presets.md).

Пресет агента `mayori` задаёт инструменты и возможности. Игровых инструкций в нём нет. Карточка персонажа и персона игрока добавляются отдельно от выбранного игрового пресета. Bundle отключает технический контекст DSH и coding-инструменты. В **Настройки → Mayori → Плагины** независимо включаются кости, проверки и чтение подробностей. [Руководство по плагинам](docs/plugins.md).

Каталог пресетов хранится на Host. Путь можно заменить в `$DSH_HOME/profiles/mayori/cordis.patch.yml`:

```yaml
- id: mayori-director
  config:
    presetsPath: /path/to/roleplay-presets
```

Прежние поля `narratorName`, `languagePolicy`, `campaignStyle` и `additionalInstructions` поддерживаются для первой инициализации каталога. После этого меняйте игровые инструкции через вкладку **Пресеты**.

## Главная страница

Бренд `Mayori Engine` открывает главную Mayori через штатную навигацию, без создания пустой сессии. Кнопка `New Session` убрана; новую историю можно начать кнопкой `Играть` на карточке персонажа. Вкладка `Главная` встречает приветствием, показывает пять последних неархивных чатов и пять недавно загруженных карточек. Под каждым разделом есть переход в полную историю или каталог. Чат открывается в прежней сессии; `Играть` на карточке начинает новую историю. Без выбранного чата и в безымянном пустом черновике главная заменяет прежний экран ввода. Именованный чат с пустым приветствием сохраняет обычное поле сообщения.

## Галерея персонажей

Пункт `Персонажи` находится в основной навигации боковой панели и доступен без активной сессии. Это штатная кнопка DSH (`sidebar.panellist`), открывающая галерею в основной области приложения: справа находятся импорт, поиск, сортировка и фильтры, слева — грид карточек. По умолчанию показываются пять карточек в ряд; можно выбрать 3, 5 или 7. Выбор сохраняется в этом браузере, на узком экране сетка уменьшает число колонок. Пагинация ограничивает страницу 20, 40 или 60 карточками (по умолчанию 20); этот выбор также сохраняется. При изменении поиска, фильтров, сортировки или лимита открывается первая страница. Если карточки удалены, номер страницы ограничивается последней доступной. Кнопка `Играть` создаёт отдельную новую сессию в текущей или последней кампании, привязывает к ней карточку, называет чат именем персонажа и открывает его. Если кампаний ещё нет, Host автоматически создаёт `~/.dsh-mayori/mayori/campaigns/default`, регистрирует каталог как Workspace и открывает чат внутри него — выбирать папку вручную не требуется. Корневой каталог можно заменить полем `campaignsPath` в конфигурации `mayori-director`. При нажатии `Играть` чат сразу содержит первое сообщение из `first_mes`, без обращения к модели. Карточки каталога не показывают выбор «Начало истории» и preview приветствия. Запуск с карточки использует основное приветствие. В окне информации («Изменить») можно выбрать альтернативное начало, посмотреть приветствие с подставленными именами и нажать «Играть»; это работает и при пустом основном приветствии. В самом чате альтернативы также переключаются до первого хода игрока. Пустое основное приветствие позволяет начать без готового сообщения. Выбранное начало сохраняется в истории, доступно модели и не меняется при обновлении карточки. Альтернативы, которые вы не выбирали, в контекст модели не передаются. В уже существующие чаты приветствия автоматически не вставляются. `Изменить` открывает информационную модалку. Галерея принимает несколько файлов за один раз:

- Character Card v2/v3 в `.json`;
- PNG-карточки v2 с блоком `chara`;
- PNG-карточки v3 с блоком `ccv3`; если в PNG есть оба блока, используется v3.

Рядом находится вкладка `История чатов`: единый список сохранённых чатов всех кампаний на этом Host, от новых к старым, без группировки по директориям. Каждая строка содержит аватар, имя персонажа, сокращённое последнее сообщение и дату. Название чата также показано, если оно отличается от имени персонажа. Без аватара используется первая буква имени. Данные берутся из сохранённого выбора персонажа и журнала сессии, включая закрытые чаты; просмотр списка не активирует сессию и не вызывает модель. Поиск работает по названию и ID чата; дата помогает различать чаты с одним персонажем. История также разбита на страницы по 20, 40 или 60 чатов. Нажатие открывает прежнюю сессию, а `Обновить` повторно загружает каталог. История включает обычные ветки и именованные чаты, созданные через `Играть`, даже до первого сообщения; пустые черновики и служебные чаты субагентов скрыты. Источник — постоянный каталог сессий DSH, поэтому история доступна после перезагрузки браузера и перезапуска Host. Поиск по тексту сообщений пока не добавлен. Кнопка `В архив` после подтверждения убирает чат из обычной истории, сохраняя переписку. Включите `Архив` и нажмите `Восстановить`, чтобы вернуть его. Архив хранится на Host и переживает перезапуски. Выполняющий работу чат DSH не архивирует: сначала дождитесь завершения или остановите работу в самом чате. При архивировании текущего чата DSH снимает его выбор и может переключить основную область; архив доступен при повторном открытии истории. Это обратимое архивирование, а не окончательное стирание данных.

Файл ограничен 16 МБ. Host сохраняет карточки в `~/.dsh-mayori/mayori/characters`, поэтому каталог не зависит от браузера, порта или Web origin. JSON карточки и исходные PNG лежат в файловом хранилище; повторный импорт того же содержимого обновляет существующую запись, неизвестные поля сохраняются без изменений. Путь можно заменить полем `charactersPath` в конфигурации `mayori-director`. Сейчас галерея не импортирует `.charx`.

Если галерея не загрузилась, нажмите **Повторить загрузку**. Повторное открытие панели также повторяет неудачный запрос. Ошибка не удаляет ранее загруженные карточки, а запоздалый ответ не заменяет результат более новой загрузки.

Снимок стандартных полей выбранного персонажа хранится отдельно в `~/.dsh-mayori/mayori/campaigns/selections/<hash-session-id>.json`. Он неизменяемый: для другого персонажа создаётся новый чат. Host восстанавливает scoped model context на ожидаемом событии `agent/created`, прежде чем DSH примет первый ввод; изменения или удаление исходной карточки не переписывают уже начатый чат. Форк чата получает собственную копию выбора. Неизвестные поля и `extensions` в модельный контекст не попадают. Штатная система DSH записывает фактически переданный модели контекст в session log. Нестандартные типы событий и патчи ядра не требуются.

В чате с первым сообщением и альтернативами появляются кнопки `‹ 1 / N ›`. До первого хода игрока они циклически переключают начало истории. Выбор сохраняется в журнале и восстанавливается после перезагрузки; модель получает только выбранное начало. После отправки сообщения приветствие блокируется. Пустое альтернативное приветствие также можно выбрать.

### Персоны игрока

Вкладка `Персоны` позволяет создать несколько персонажей игрока: указать имя, описание, необязательную подпись и аватар PNG/JPEG/WebP до 2 МБ. Сохраните персону и нажмите `Использовать по умолчанию`, чтобы новые чаты начинались с ней. `Играть в этом чате` сохраняет введённые изменения и закрепляет персону за открытым чатом. До первого хода эта операция также обновляет приветствие; после начала игры предыдущая переписка сохраняется.

Имя заменяет `{{user}}`, описание заменяет `{{persona}}` и передаётся модели как описание персонажа игрока. Подпись помогает различать персоны, аватар показывается в списке и справа от каждого сообщения игрока; они не передаются модели. Аватар персонажа из PNG-карточки находится слева от каждого его сообщения, включая приветствие. Нажатие, Enter или Space открывают изображение целиком; окно закрывается кнопкой, Escape или нажатием за его пределами и возвращает фокус на аватар. Клавиши аватара не отправляют сообщение и не создают новый чат. Если изображения нет, показывается первая буква имени. Без выбранной персоны используется имя `Игрок`. Каталог хранится на Host в `~/.dsh-mayori/mayori/personas`; путь настраивается через `personasPath`. Каждый чат хранит свою копию: редактирование или удаление персоны из каталога не меняет уже созданные чаты.

В панели разговора сначала идёт `Чат`, затем `Trajectory`. Контекст карточки и описание игрока находятся в отдельном разделе системного сообщения после инструкций ведущего, перед приветствием и вводом игрока, включая провайдеры с обновлением prompt внутри истории. В Trajectory раскрытие SYSTEM показывает этот раздел в фактически сохранённом запросе. Старые запросы сохраняют исходный порядок; новый порядок применяется со следующего обращения к модели после перезапуска Host.

### Базовые шаблоны SillyTavern

Подстановка работает в приветствиях, их предварительном просмотре в окне информации и стандартных модельных полях карточки. Имена макросов нечувствительны к регистру, допускают пробелы вокруг имени. Поддерживаются:

- `{{user}}`, `{{char}}`, `{{persona}}`, `{{charIfNotGroup}}`, `{{group}}`, `{{groupNotMuted}}`, `{{notChar}}`;
- `{{description}}` / `{{charDesc}}`, `{{personality}}` / `{{charPersonality}}`, `{{scenario}}`, `{{mesExamples}}` / `{{charExamples}}` / `{{charExamplesRaw}}`;
- `{{charPrompt}}`, `{{charJailbreak}}`, `{{charVersion}}`, `{{charCreator}}`;
- `{{newline}}`, `{{space}}`, `{{trim}}`, `{{noop}}`, комментарии `{{// …}}` и старые обозначения `<USER>` / `<BOT>`;
- `{{date}}`, `{{time}}`, `{{isodate}}`, `{{isotime}}`, `{{weekday}}`: UTC-время создания чата, сохранённое для повторяемой подстановки;
- `{{original}}` и `{{input}}`: пустая строка, поскольку в карточке нет исходного prompt override или активного draft input.

Текст карточки не является шаблоном DSH: `{{cwd}}`, `{{model}}`, неизвестные и некорректные конструкции остаются данными. STscript, переменные SillyTavern, случайный выбор и броски не исполняются. Это базовый набор совместимых подстановок; исходная карточка сохраняется без изменений.

### Миграция с прежней версии

Переустановите локальный пакет через `pnpm dlx @deepseek-ai/dsh@0.2.1-alpha.2 plugin --profile mayori add C:\pet_projects\Mayori` и полностью перезапустите DSH. В профильном `cordis.patch.yml` проверьте переопределения `system-prompt`: поле `persona` заменено на `personaPrefix` и `personaSuffix`. Профильные overrides применяются последними и могут перекрыть новый preset; для игры выбирайте `mayori`. Browser вкладку перезагрузите после перезапуска.

Карточки галереи сохраняются без изменений. Старые сессии с обязательными событиями `mayori/character-selected`, созданные пропатченным DSH, не конвертируются автоматически: штатный DSH может отказаться читать такие журналы. Не удаляйте и не редактируйте их вручную; перед отдельной конвертацией сохраните резервную копию всего DSH home. Обычные сессии без этих событий мигрирует сам DSH.

## Броски кубиков

Переключатель «Кости» в **Настройки → Mayori → Плагины** добавляет native инструмент `rollDice`. Любое положительное число граней в пределах лимита допустимо без регистрации. Поддерживаются арифметика, `kh`/`kl`, взрывы `!`, перебросы `r`/`ro`, сравнения, подсчёт успехов, ссылки на результаты текущего batch и ленивые условия.

`rolls` сохраняет форму дерева. Обычный ответ содержит только `rollId`, `values` и непустой `errors` при ошибках. Листья — числа/boolean, ошибки отдельных полей дают null; независимые поля продолжают вычисляться. Полная запись версии 3 сохраняет грани, ветки и ссылки в журнале и карточке, включая форк и восстановление. Модель читает её через `getRollDetails({ "rollIds": ["id-из-ответа"] })`, без новых бросков. Старые результаты остаются читаемыми. Сохранённый пул внутри batch можно исследовать через `count`, `countFaces` и `face`. `details: true` сохранён для совместимости; подробности прежнего броска читайте только по его `rollId`.

Формат запросов, примеры условий, семантика модификаторов и Config описаны в [руководстве по кубикам](docs/dice.md).

Инструмент `resolveCheck` отдельно возвращает натуральную грань, модификатор, итог, сложность, явный исход (включая крит), условный урон и настроенное последствие. Правила и формулы фиксируются до броска и сохраняются в журнале. Профили, примеры и Config описаны в [руководстве по проверкам](docs/rules.md).

Игровые возможности независимы и переключаются на странице Mayori в штатных настройках. Проверки автоматически используют Dice provider без дополнительного `rollDice`, если свободные броски выключены. Настройки применяются также к существующим чатам. Публичные entries `dsh-mayori/dice`, `/rules`, `/roll-history` доступны для собственных композиций; `/mechanics` сохранён для совместимости. См. [настройку плагинов](docs/plugins.md) и [чтение подробностей](docs/roll-history.md).

## Статус

Mayori находится на ранней стадии. Текущий bundle задаёт модельный опыт, заменяет Web sidebar на расширяемую RPG-навигацию и предоставляет настоящие числовые броски и проверки с явными исходами. Отдельные сервисы состояния кампании, игровых rulesets и полноценный RPG-интерфейс ещё не реализованы.
