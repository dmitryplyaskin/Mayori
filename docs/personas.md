# Персоны

Персона задаёт имя и описание персонажа, за которого играет пользователь. Откройте **Персоны**, создайте запись, заполните имя и описание и нажмите **Сохранить персону**. Подпись помогает различать записи. Аватар — PNG, JPEG или WebP; отдельного лимита 2 МБ у персон нет, действует общий предел медиахранилища 16 МБ. Подписи, названия блоков, привязки и аватары не передаются модели.

Слева — библиотека с поиском по имени, подписи и базовому описанию, сортировкой по имени, длине описания и количеству привязок. Справа — редактор с вкладками **Описание**, **Блоки**, **Настройки** и **Предпросмотр**. Имя, подпись и смена аватара доступны над вкладками. Кнопки сохранения и применения в чате всегда доступны внизу. Ctrl+S (Cmd+S на macOS) сохраняет открытый редактор. На узком экране библиотека раскрывается кнопкой **Библиотека**, а текст редактора прокручивается отдельно.

В меню **Действия** есть **Создать копию**, **Отменить изменения** и **Удалить персону**. Копия сохраняет текущие поля редактора и аватар; привязки самой персоны к персонажам в копию не переносятся. У каждой персоны свой несохранённый черновик: можно переключать записи библиотеки и панели, не теряя текст. Черновики живут до перезагрузки страницы; отметка **Не сохранено** отличает их от сохранённых записей. **Отменить изменения** возвращает сохранённую запись только выбранной персоны. При первом открытии редактор выбирает персону по умолчанию или первую запись библиотеки.

## Выбор для чата

- **Использовать по умолчанию** на вкладке **Настройки** выбирает сохранённую персону для новых чатов.
- В разделе **Привязки к персонажам** кнопка **Добавить текущего персонажа** выбирает эту персону для новых чатов с открытым персонажем. У одного персонажа может быть одна привязанная персона; она имеет приоритет перед выбором по умолчанию.
- **Играть в этом чате** сохраняет поля редактора и явно меняет персону в открытом чате.
- Команда `/persona` меняет выбор непосредственно из чата. **Без персоны** выбирает имя `Игрок` и пустое описание независимо от default и привязок.

Каждый чат сохраняет свою копию персоны. Изменения каталога, default и привязок применяются к будущим выборам. Старые чаты сохраняют прежний текст, даже если запись удалена. Чтобы применить новую редакцию, снова выберите персону в нужном чате. До первого хода выбор обновляет авторское приветствие; после начала игры прежние сообщения сохраняются.

## Дополнительные описания

Идея перенесена из SillyTavern Persona Management Extended: базовое описание остаётся отдельно, а одежду, биографические детали и условия сцены можно хранить в переключаемых блоках.

На вкладке **Блоки** слева расположен список дополнений, справа — редактор выбранного элемента. На узком экране список заменяется компактным выбором блока. **Добавить блок** создаёт текстовый блок. **Добавить группу** создаёт папку, **Добавить блок в группу** добавляет её содержимое. Выключенная группа исключает все дочерние блоки. Глубина — один уровень групп. Стрелки меняют порядок среди соседей; итоговый текст использует тот же порядок. Пустые блоки пропускаются, пробелы внутри непустого текста сохраняются. Переключение вкладок и выбранного блока не выключает дополнения. Стрелки имеют подсказки при наведении и клавиатурном фокусе. По вкладкам можно перемещаться стрелками, Home и End.

Раздел **Автоматическая активация** доступен у блоков, групп и элементов группы. Включите **Включать по условиям** и задайте одно или несколько условий:

- текущий чат;
- текущий персонаж;
- текст, содержащийся в описании персонажа, без учёта регистра.

Достаточно любого совпадения. В автоматическом режиме ручная включённость не используется. Условия дочернего блока проверяются только внутри активной группы. Пустое правило ничего не включает. Правила вычисляются по сохранённому описанию карточки, а не по переписке или ответу модели.

Условия проверяются при создании чата или явном выборе персоны. Итог сохраняется в snapshot чата. Форк наследует этот итог, включая блоки, активированные в родительском чате; он не переключает их автоматически из-за нового session ID.

## Вариант и шаблон

**Другой вариант описания** позволяет редактировать текст для модели отдельно от базового описания. При выключении используется база. **Сделать базовым описанием** переносит вариант в базу; сохраните персону, чтобы записать изменение. Включённый пустой вариант исключает базовый текст, но оставляет активные дополнения.

В разделе **Сборка описания** на вкладке **Настройки** задаётся разделитель блоков; по умолчанию `\n\n`. Поддерживаются `\n`, `\r`, `\t`, `\\`; пустая строка склеивает блоки без разделителя. Итог сначала собирается из выбранного базового текста и активных дополнений, затем подставляется во все `{{PROMPT}}` включённого шаблона. Например:

```text
<player>{{PROMPT}}</player>
```

Включённый шаблон обязан содержать `{{PROMPT}}`. Пустое описание не оборачивается. На вкладке **Предпросмотр** показан результат для условий открытого чата, либо без условий чата. `{{user}}`, `{{char}}` и другие поддерживаемые макросы раскрываются при проекции в контекст и приветствие. `{{persona}}` возвращает собранное описание.

## Хранение и границы

Каталог хранится на Host в `personasPath/personas.json`, по умолчанию `~/.dsh-mayori/mayori/personas`. Формат 1 остаётся совместим с прежними записями без блоков. Новые поля: `blocks`, `prompt`, `descriptionOverride`, `characterIds`. Условия, порядок и названия имеют строгую валидацию. Лимиты: 256 блоков вместе с группами, до 32 000 символов в одном тексте, до 128 000 в исходных описаниях и до 256 000 в собранном тексте.

Persona Service разрешает `resolve(id, context)` с `sessionId`, `characterId` и `characterDescription`. Character Session Provider сохраняет полную копию и `promptSnapshot` с итоговым описанием и активными ID. Выбор выполняется под `agent.runMaintenance`. Модельная проекция содержит только имя и итоговое описание; штатная система prompt sections записывает её в session log. Restore и fork не читают актуальные тексты из каталога. Runtime-подмена глобальных переменных и патчи `agent-loop` не используются.

Это реализация основных возможностей PME для архитектуры Mayori. Regex-условия, lorebooks, Author’s Note, вставка на глубину истории, групповые чаты, импорт/экспорт персон SillyTavern и синхронизация имени в старых сообщениях не реализованы. Описание персоны остаётся в системном разделе контекста карточки. Отдельного переключателя Normal/Advanced не требуется: редактор расширяет существующую панель Mayori.

## Проверка

`pnpm run check` проверяет сборку, границы модулей, валидацию, активацию, сборку текста, приоритет выбора, сохранение копий, восстановление, обновление приветствия, независимые черновики и изменение дерева блоков. `scripts/browser-personas-smoke.js` проверяет редактор в изолированном DSH с `dsh-smoke-probe`: создание, группы, reorder, tooltips, поиск, вариант, шаблон, default, копирование, применение в чате, независимые черновики, reload, клавиатуру вкладок, Ctrl+S, компактный выбор блока и ширины 1280/390/320 px. Проверяются контраст основных текстов в обеих темах и доступность сохранения в эмуляции увеличения: viewport 640×500 CSS px с плотностью 2×. Запускайте его только во временном профиле, по схеме из [руководства разработчика](development.md).
