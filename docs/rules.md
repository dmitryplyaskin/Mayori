# Проверки, криты и последствия

`resolveCheck` разрешает числовую проверку по заранее выбранному профилю правил. Это отдельный Rules capability, использующий настоящий `DiceService`; инструмент не меняет HP, инвентарь или состояние кампании.

```json
{
  "purpose": "Атака мечом",
  "profile": "d20-attack",
  "modifier": 6,
  "target": 15,
  "mode": "advantage",
  "damage": { "normal": "1d6 + 3", "critical": "2d6 + 3" }
}
```

`profile` и `target` обязательны. `modifier` по умолчанию 0; `mode` — `normal`, `advantage` или `disadvantage`, по умолчанию `normal`. Преимущество выбирает лучший из двух кубиков, помеха — худший. Крит определяется только выбранной гранью. Отброшенная единица или двадцатка не влияет на статус.

## Профили по умолчанию

| ID | Механика |
|---|---|
| `standard` | d20 + modifier против target; автоматических исходов и критов нет |
| `d20-critical` | Натуральная 20 — критический успех; натуральная 1 — критический провал, независимо от модификатора и сложности |
| `d20-attack` | Натуральная 20 — критический успех; натуральная 1 — автоматический обычный провал |

Это числовые политики проверки, а не полный ruleset D&D. Выбирайте только профиль, соответствующий установленным правилам действия. Сам факт броска d20 не включает критические исходы. По умолчанию ни один профиль не назначает дополнительных негативных эффектов.

## Config и последствия

Профили находятся в валидируемом `Config.profiles` плагина `mayori-mechanics` (`dsh-mayori/mechanics`) в `config.plugins` пресета `mayori`. При переопределении списка плагинов сохраняйте весь список и изоляцию `mayoriDice`, `mayoriRules` и `mayoriRollHistory`. `dsh-mayori/dice` остаётся отдельным публичным плагином с `rollDice` и чтением сохранённых подробностей.

Каждый профиль содержит:

- `id`: уникальный идентификатор из строчных латинских букв, цифр и дефисов, начинается с буквы, до 64 символов;
- `version`: непустая строка до 64 символов; изменяйте её при изменении правил;
- `sides`: 2–1 000 000 000 в пределах Dice `maxSides`;
- `criticalSuccessMin`: выбранная грань не меньше порога означает критический успех и попадание;
- `criticalFailureMax`: выбранная грань не больше порога означает критический провал;
- `naturalFailureMax`: выбранная грань не больше порога означает автоматический провал;
- `failureEffect`: необязательное фиксированное последствие провала, по умолчанию пустая строка;
- `criticalFailureEffects`: необязательная равновероятная таблица последствий критического провала, по умолчанию пустой массив.

Пороги по умолчанию 0 (выключены), иначе это целые грани в пределах кубика. Диапазоны успеха и провала не пересекаются. Доступно 1–32 профиля; таблица содержит до 100 непустых строк, каждая до 1000 символов. `failureEffect` также ограничен 1000 символами. Таблица требует включённого критического провала.

Например, профиль для правил стола:

```yaml
profiles:
  - id: house-d20
    version: '1'
    sides: 20
    criticalSuccessMin: 20
    criticalFailureMax: 1
    naturalFailureMax: 1
    failureEffect: 'Действие не достигло цели.'
    criticalFailureEffects:
      - 'Шум привлекает внимание.'
      - 'Персонаж теряет равновесие до следующего хода.'
```

Таблица бросается реальным dN только при критическом провале. Её результат заменяет фиксированный эффект; при обычном провале используется `failureEffect`. Модель описывает установленное последствие в сцене, сохраняя добровольные решения игрока. Инструмент не применяет его к скрытому состоянию.

## Урон и ошибки

Урон необязателен. Если он указан, `normal` обязателен; профиль с критическим успехом также требует `critical`. Формулы задаются до броска. Для удвоенных костей `1d6+3` превращается в `2d6+3`; для другой механики задайте соответствующую формулу. Допустимы самостоятельные числовые Dice-выражения без ссылок на поля проверки.

При успехе бросается только применимая формула. При провале кости урона не бросаются. Неверные профиль, параметры, формулы и глобальные бюджеты отклоняются до случайности. Предварительный бюджет Dice включает обе ветки урона и потенциальный кубик таблицы, даже когда они не будут выбраны. Runtime-лимит считает реальные грани, включая взрывы и перебросы.

Ошибка во время броска урона сохраняет уже разрешённую проверку и фактические грани, возвращает `damage: null` и `errors`. Неполный урон не становится итогом; повторного броска нет. Отмена или отказ генератора остаются ошибками вызова.

## Результат и журнал

Полная запись версии 1 содержит `rollId`, полный snapshot `rules`, нормализованный `request`, `check`, `damage`, `consequence` и `errors`. `check` включает `natural`, `modifier`, `total`, `target`, `margin`, `outcome` (`success`, `failure`, `critical_success`, `critical_failure`) и машинную причину `reason`. `margin` — total минус target, даже при автоматическом исходе.

По умолчанию модель получает `rollId` и `check` без вычисляемого `margin`. Поле `damage` содержит только число при разрешённом уроне, `consequence` — только выбранный текст при установленном последствии, `errors` — только непустой массив ошибок. Отсутствие `damage` не выдаёт ошибку урона за ноль: такую ошибку обозначает `errors`. `check: null` означает, что сама проверка не разрешена. Отсутствие `consequence` не разрешает модели придумывать дополнительный штраф.

Краткий ответ исключает `request`, snapshot правил, таблицы, `observations` и Dice trace. Описание инструмента перечисляет только идентификаторы/версии профилей, размер кубика и включённые пороги. Полный результат всегда записывается в `tool/result` metadata `{ kind: 'mayori-check', result }`. [getRollDetails](roll-history.md) читает его по `rollId`. Совместимый `details: true` возвращает полную запись сразу при новом вызове; для проверки прежнего результата не вызывайте `resolveCheck` повторно.

Карточка показывает натуральную грань, модификатор, итог, сложность, исход, урон и последствие без раскрытия. Подробности содержат snapshot правил и полный trace. Reader проверяет совпадение content с metadata и записанными гранями; повреждённые и неизвестные версии показываются исходным текстом. Возобновление и форк читают запись без запуска provider и без использования текущего Config.

Сид для игровых бросков не введён. Исторические результаты воспроизводятся чтением журнала; production использует `crypto.randomInt`, а тесты подставляют заданные последовательности граней.
