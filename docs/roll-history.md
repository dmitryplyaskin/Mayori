# Подробности сохранённых бросков

Обычные вызовы `rollDice` и `resolveCheck` возвращают компактный результат и `rollId`. Полная запись остаётся в metadata журнала, доступна карточке и не отправляется модели. Раскрытие карточки пользователем не добавляет её JSON в контекст модели.

Когда краткого результата недостаточно, модель вызывает:

```json
{ "rollIds": ["id-из-первого-ответа", "id-из-второго-ответа"] }
```

Инструмент `getRollDetails` принимает от 1 до 20 разных идентификаторов. Один `rollId` соответствует одному вызову, включая все выражения его batch. Возвращает `{ rolls: [{ rollId, tool, result }] }` в порядке запроса. `result` содержит полную сохранённую запись: выражения, грани, выбор кубиков, перебросы, взрывы, ветки и ссылки; для `resolveCheck` также исходный запрос, snapshot правил и выбранное последствие. Это чтение, не новый бросок или применение последствий к состоянию кампании.

Доступен только журнал вызывающего чата; параметра для другого sessionId нет. Resume и форк сохраняют исходные `rollId`. Чтение использует весь журнал, включая результаты, исключённые из текущего модельного контекста компактацией. Перезапуск Host не требует памяти процесса или отдельного хранилища. Старые записи без `rollId` можно прочитать по сохранённому `toolCallId`.

Неизвестный, неоднозначный или повреждённый идентификатор даёт отдельную запись `{ rollId, error: { code, message } }`, не отменяя остальные результаты. Коды: `not_found`, `ambiguous_id`, `invalid_record`. Ошибки чтения не требуют повторного броска. Неверный запрос и отсутствие вызывающего чата дают ошибку вызова до чтения.

Подробный ответ входит в журнал обычного tool result и контекст последующего шага модели. Поэтому модель запрашивает его только при необходимости. Полная запись и краткий результат проходят проверку согласованности; изменённые текущие профили не переинтерпретируют историю.

Capability состоит из `RollHistoryService.read(session, rollIds)`, `SessionRollHistoryProvider` и native Consumer `getRollDetails`. Сервис `mayoriRollHistory` регистрируется через Cordis и изолируется в пресете вместе с Dice/Rules. Его также включает публичный standalone `dsh-mayori/dice`. Выгрузка плагина удаляет сервис и инструмент.
