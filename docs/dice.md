# Механики rollDice

`rollDice` принимает `{ rolls, purpose?, details? }`. `rolls` — дерево объектов и массивов со строковыми выражениями в листьях. Все явно указанные листья вычисляются; пустые вложенные контейнеры допустимы. `purpose` задаётся до броска. `details` по умолчанию false и влияет только на ответ модели: полная трассировка всегда записывается в presentation metadata сессии.

```json
{
  "purpose": "Атака и урон",
  "rolls": {
    "attack": "2d20kh1 + 5",
    "hit": "$attack >= 15",
    "damage": "if($hit, 2d6!ro<3 + 3, 0)",
    "successes": "count(5d10, >=8)"
  }
}
```

Обычный ответ содержит только `{ rollId, values }` и непустой `errors` при ошибках. Грани, `observations`, purpose и трассировка не отправляются модели. `rollId` — сохранённый идентификатор вызова; один вызов может содержать весь batch. Подробности читает [getRollDetails](roll-history.md), без новых бросков. Карточка использует полный журнал и по-прежнему показывает выбранные грани без раскрытия. Для явных критов и последствий используйте [resolveCheck](rules.md); для числовых результатов включайте нужные `face`, `count` или `countFaces` в исходный batch.

## Выражения

| Запись | Значение |
|---|---|
| `d37`, `3d6` | Один произвольный числовой кубик; сумма трёх независимых d6 |
| `+ - * /`, скобки, унарные `+ -` | Арифметика; деление не округляется |
| `floor(x)`, `ceil(x)`, `round(x)` | Явное округление; `round(-1.5)` равно -1 |
| `max(a,b,...)`, `min(a,b,...)` | Наибольший/наименьший итог, как минимум два аргумента |
| `2d20kh1`, `4d6kl2` | Сумма K лучших/худших исходных кубиков или цепочек |
| `d6!` | Максимальная принятая грань добавляет ещё один кубик; взрывы повторяются |
| `d6ro<3` | Каждую грань, включая дополнительные грани взрывов, перебросить не более одного раза, если она меньше 3 |
| `d6r<3` | Перебрасывать грань, пока она меньше 3 |
| `> >= < <= == !=` | Сравнение итогов, возвращает boolean |
| `count(5d10, >=8)` | Количество принятых исходных кубиков/цепочек, удовлетворяющих порогу |
| `count($pool, >=8 and !=10)` | Повторный подсчёт сумм цепочек сохранённого пула без новых бросков |
| `countFaces($pool, >=8)` | Подсчёт отдельных принятых граней выбранных цепочек, включая взрывы |
| `face($pool)` | Единственная принятая выбранная грань, например d20 после преимущества |
| `true`, `false`, `not`, `and`, `or` | Строгая boolean-логика, без преобразования чисел в boolean |
| `if(test,then,else)` | Выполнить только выбранную ветку |
| `$attack` | Уже вычисленный результат поля верхнего уровня `attack` |
| `ref(["damage","a.b"])`, `ref(["checks",0])` | Точный путь со строковыми ключами объектов и числовыми индексами массивов |

`count`, `countFaces` и `face` принимают одну группу кубиков или ссылку на лист, содержащий только группу кубиков с модификаторами, либо на её alias. Арифметические итоги не являются пулами: `count($total, >=8)` при `total: '2d6+3'` даёт `pool_expected`. Обычная ссылка `$pool` по-прежнему возвращает сумму. `face` требует ровно одну принятую выбранную грань; многокостные и многогранные взрывные пулы дают `ambiguous_face`.

Порог для `count`, `countFaces`, `r` и `ro` — числовой литерал, включая знак и десятичную часть. В `count` и `countFaces` условия объединяются `and`, `or`, `not` и скобками. `5d10 >= 8` сравнивает сумму с 8, а `count(5d10, >=8)` считает отдельные результаты. При `kh`/`kl` подсчёт учитывает только выбранные цепочки; переброшенные грани исключаются. Каждый явный кубик и каждое повторение одинаковой формулы бросается независимо; `max(2d6,2d6)` бросает две независимые группы. Для нескольких подсчётов сохраните один пул вместо вычитания результатов двух независимых бросков.

```json
{
  "rolls": {
    "pool": "6d10!",
    "successes": "countFaces($pool, >=8)",
    "tens": "countFaces($pool, ==10)",
    "otherSuccesses": "countFaces($pool, >=8 and !=10)",
    "attack": "2d20kh1",
    "natural": "face($attack)",
    "total": "$attack + 6"
  }
}
```

Цепочка `[10,10,8]` даёт один успех для `count(..., >=8)` и три для `countFaces(..., >=8)`. `r>=10` заменяет десятку новой гранью, а `!` сохраняет её и добавляет грань; выбирайте семантику установленной системы.

Приоритет: скобки/функции/кубики и модификаторы, унарные знаки/`not`, умножение/деление, сложение/вычитание, сравнения, `and`, `or`. Операции одного уровня ассоциативны слева. Используйте `not ($attack >= 15)` для отрицания сравнения. Равенство требует одинаковых типов, упорядоченные сравнения и арифметика требуют чисел. Логические операции и условие `if` требуют boolean. `and`/`or` не вычисляют правую часть, если ответ уже известен.

## Взрывы, перебросы и выбор

Для каждой исходной кости сначала выполняется переброс по правилу; затем принятая максимальная грань взрывается. Дополнительная грань проходит тот же процесс. Допускается один модификатор переброса, один `!` и один `kh`/`kl`; выбор должен стоять последним. `d6!ro<3` и `d6ro<3!` имеют одинаковую семантику. Модификаторы костей нечувствительны к регистру и допускают пробелы.

Цепочка `[6,6,3]` имеет сумму 15. В `4d6!kh3` выбираются три целые цепочки по их суммам; дополнительные грани не становятся отдельными исходными костями. Равные цепочки выбираются по порядку исходных костей. Переброшенные грани сохраняются, но исключаются из суммы. `ro` применяется один раз к каждой очередной грани, а не один раз ко всей цепочке. `d1!` и повторный переброс с условием, совпадающим со всеми возможными гранями, отклоняются до генерации случайности.

## Ссылки и ленивые условия

Имена в `$name` ограничены латинскими буквами, цифрами и `_`, первая позиция — буква или `_`. Для любых других имён, вложенности и массивов используйте `ref([...])`. Ссылка всегда на лист выражения текущего batch; ссылок на контейнеры, прошлые вызовы или скрытое состояние нет. Она использует один сохранённый результат и не перебрасывает кости. Поддерживаются ссылки вперёд; порядок ключей не ограничивает доступность результата.

Синтаксис, существование путей, циклы и глубина зависимостей проверяются во всём запросе, включая невыбранные ветки, до бросков. Вычисляются только выбранная ветка и действительно используемые зависимости. Константные арифметические ошибки выявляются заранее, кроме веток с ещё неизвестным условием. Все самостоятельные листья всё равно являются запрошенными результатами: чтобы не бросать урон при промахе, поместите кубики внутри `if`, а не в отдельное безусловное поле.

```json
{
  "rolls": {
    "save": "d20 + 3 >= 14",
    "baseDamage": "3d6",
    "damage": "if($save, floor($baseDamage / 2), $baseDamage)"
  }
}
```

## Ошибки и журнал

Полная запись версии 3 содержит `schemaVersion: 3`, `rollId`, необязательную нормализованную `purpose`, `values` той же формы, `observations`, массив `errors` и `details`. Краткий ответ модели оставляет только `rollId`, `values` и непустой `errors`. Лист значения — число, boolean или null при ошибке. `errors` содержит `{ path, code, message }` для каждого ошибочного листа. Ошибки разбора, арифметики и ссылок не отменяют независимые поля; использование ошибочного результата даёт `dependency_failed`. Неиспользованная ветка не требует успешно вычислить её зависимости.

Неверная структура дерева, число узлов/листьев, глубина дерева и превышение бюджета потенциальных исходных костей отклоняют весь запрос до бросков. Этот предварительный бюджет считает обе ветки и все аргументы валидных выражений, но не считает выражения, не прошедшие разбор/константную проверку. Отдельно runtime-бюджет считает каждую реально выпавшую грань, включая отброшенные, перебросы и взрывы. Если он исчерпан, последующие поля, которым нужны новые броски, тоже получают `dice_limit`; константы и ссылки на успешные результаты доступны.

Отмена вызова и отказ самого генератора случайности остаются ошибками вызова. Они не подменяются вычисленными значениями.

`extra_roll_limit` или `dice_limit` возвращает null для поля и сохранённые фактические грани; неполная цепочка не выдаётся за итог. Автоматических повторов ошибочного выражения нет. Предел числового итога — конечное число с абсолютным значением не выше `Number.MAX_SAFE_INTEGER`.

`getRollDetails({ "rollIds": ["идентификатор-из-ответа"] })` возвращает полную записанную трассировку каждого поля: исходное выражение, путь, итог/ошибка, ссылки, выбранные ветки и группы кубиков. Группа содержит `count`, `sides`, `results` и `draws`: глобальный номер броска, исходную кость, причину (`initial`, `explode`, `reroll`), индекс заменённой грани для переброса. Модифицированные группы содержат `chains` с индексами принятых граней и суммой завершённой цепочки. `keptIndices` указывает принятые грани выбранных цепочек. Группы и цепочки могут быть неполными при ошибке; суммы незавершённых цепочек отсутствуют. `details: true` сохранён для совместимости и возвращает полную запись сразу при новом броске; для проверки старого броска используйте только его `rollId`.

Полный ответ всегда хранится в `tool/result` metadata `{ kind: 'mayori-dice', result }`. Карточка восстанавливает его без выполнения формул; resume/fork не создают новых бросков. Старые результаты версий 2, 1 и без версии сохраняют прежнюю семантику при чтении. Неизвестная версия/повреждённый payload показывает raw content. Инструмент выполняет заданную механику; трактовка игровых последствий и добровольные решения игрока остаются за установленными правилами и игроком.

## Config

В отдельных настройках Mayori настройка «Свободные броски» раздела «Кости и проверки» включает `rollDice`. Лимиты задаются валидируемым `Config.dice` entry `dsh-mayori/optional-plugins` или Config самостоятельного `dsh-mayori/dice`. Положительные целые ограничены верхней границей. Rules автоматически сохраняет Dice provider при выключенном инструменте. [Руководство по плагинам](plugins.md).

| Config | Default | Ceiling |
|---|---:|---:|
| `maxSides` | 1 000 000 | 1 000 000 000 |
| `maxDice` | 1 000 | 100 000 |
| `maxExpressions` | 100 | 1 000 |
| `maxDepth` | 16 | 64 |
| `maxNodes` | 1 000 | 10 000 |
| `maxExpressionLength` | 1 024 | 8 192 |
| `maxExpressionDepth` | 64 | 128 |
| `maxPurposeLength` | 300 | 2 000 |
| `maxExtraRollsPerDie` | 100 | 10 000 |
| `maxDependencyDepth` | 64 | 128 |

`maxExtraRollsPerDie` считает все дополнительные броски одной исходной кости: и перебросы, и взрывы. `maxDependencyDepth` считает листья в самом длинном пути зависимостей, включая сам лист. Длина цели включает крайние пробелы до нормализации. Лимиты выражения применяются по полям; лимиты структуры и потенциальных исходных костей — ко всему запросу.
