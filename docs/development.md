# Разработка

Оптимизация каталогов, медиа и превью описана в [performance guide](performance.md). `node scripts/performance-benchmark.js [count]` сравнивает прежний полный listing и новую страницу в отдельных процессах на временных данных. После изменения каталогов или кешей проверяйте `pnpm run check`, isolated profile / `--dump-config` и browser smoke для галереи и аватаров. Avatar smoke дополнительно проверяет размеры миниатюр и загрузку оригиналов только при раскрытии.

## Требования

- Node.js `^22.19.0` или `>=24.0.0`;
- pnpm 11;
- DeepSeek Harness `0.2.1-alpha.2` для интеграционного smoke test; полный форк не нужен.

## Быстрый цикл

```sh
pnpm install
pnpm run check
```

`check` проверяет синтаксис entry point и запускает unit tests через встроенный `node:test`. Исходник поставляется как ESM JavaScript, поэтому GitHub-установка не требует build script.

Browser half собирается отдельно в формат lazy client module, который ожидает Web DSH:

```sh
pnpm run bundle
```

Команда создаёт `lib/client.js` и source map. Оба artifact входят в Git, чтобы установка из GitHub не выполняла код сборки на машине пользователя.

Выпадающие поля используют общий `src/client/components/select.jsx`: тот же `Menu` и `IconChevronDownOutlineRegular` из публичного `@deepseek-ai/dsh-client-ui-primitives`, что и штатные настройки DSH. Примитивы предоставляет таблица browser platform modules Web DSH; сборка оставляет этот import внешним рядом с React. Копии меню, его CSS и дополнительная plugin registration не нужны. `Menu` владеет portal, размещением, прокруткой, клавиатурой, закрытием и восстановлением фокуса. Поле передаёт подпись, выбранный ID, варианты и действие; числовые значения преобразуются в потребителе.

Меню по умолчанию выводится через portal, чтобы его не обрезали панели. Поле приветствия внутри native `<dialog>` использует штатный inline-режим `Menu`: список остаётся внутри top layer диалога. Повторный выбор того же значения закрывает меню без записи; доступное описание кнопки включает выбранное значение.

Во временном профиле browser-сценарии `browser-presets-smoke.js`, `browser-home-smoke.js` и `browser-revisions-smoke.js` покрывают все 11 полей: пресеты, фильтры/колонки галереи, пагинацию, приветствие, ветки и контекст запросов. Проверки используют реальные `menuitem`, включая клавиатуру, Escape/возврат фокуса, закрытие снаружи, длинные списки и узкий экран. Общие browser-операции выбора находятся в `scripts/browser-select.js`.

## Где размещать изменения

Полное дерево и правила зависимостей описаны в [структуре исходников](architecture.md#структура-исходников).

- Игровая возможность: `src/features/<feature>/host`, `client`, `domain` или `shared` по назначению кода. Контракт сервиса, durable store и Provider разделены там, где имеют самостоятельную ответственность.
- Подключение Host providers: `src/host/application.js`; схема deployment-настроек: `src/host/config.js`; HTTP адаптация: `src/host/transport`.
- Browser contributions и wiring: `src/client/plugin.js`; главная и навигация: `src/client/shell`; повторно используемые компоненты и transport: `src/client/components` и `infrastructure`.
- Unit tests: соответствующий каталог `test/features/<feature>`, либо `test/host`, `test/client` и `test/shared`. Smoke scripts остаются в `scripts`.

`pnpm run check` собирает browser artifact и запускает все тесты, включая архитектурные проверки границ Host/browser, запрет циклов и проверку package allowlist. Изменяя расположение Host source, обновите `package.json.files` и внутренние imports; публичные package exports сохраняйте. `lib` изменяется через сборку, не вручную. Для проверки реального содержимого архива используйте `npm pack --dry-run --json`.

При переносе кода или изменении wiring установите checkout в отдельный временный DSH profile и проверьте `--dump-config` по инструкции ниже. Profile composition должна сохранить director, preset-scoped Dice/Rules и browser entry. Рабочий профиль игрока для этих проверок не используется.

## Проверка в локальном DSH

`node scripts/storage-isolation-smoke.js <dsh-cli-bin.js>` устанавливает checkout
через публичный CLI в временный профиль, проверяет `--dump-config` и запускает
Mayori рядом с обычной Web-композицией. Оба профиля создают настоящие чаты в
одной рабочей папке; native persistence и Session Controller должны видеть
только собственные ID, включая повторный запуск после остановки. Probe также
проверяет разрешённые Config paths журналов, registry, attachments, credentials
и поискового индекса. Для опубликованного CLI используйте
`node scripts/storage-isolation-smoke.js <pnpm.js> --published`: этот режим
выполняет реальные команды `pnpm dlx @deepseek-ai/dsh@0.2.1-alpha.2`.
Сценарий не вызывает модель и печатает путь к временным данным для инспекции.

Для сжатия истории выполните `node scripts/compaction-smoke.js <URL-test-Host>` в изолированном профиле с probe. Сценарий проверяет порог, инструмент compactHistory ниже порога, отсутствие служебного текста, точную сохранённую инструкцию, исходные события, изоляцию, обновление, отключение и native fork. `node scripts/browser-plugin-settings-smoke.js <URL-test-Host> <output-directory>` дополнительно проверяет отдельную модалку Mayori: пустую вкладку «Основные», клавиатурное переключение вкладок, сворачиваемые разделы, поиск по названию и описанию, форму, валидацию, сохранение черновика при фильтрации и навигации, ошибки записи и сохранение после перезагрузки. Сценарий проверяет отсутствие раздела Mayori в штатных настройках DSH, Escape и возврат фокуса, светлую/тёмную тему и ширины 1280/390/320 px. Настройки и устройство журнала описаны в [руководстве](compaction.md).

Обычный пользователь устанавливает bundle с GitHub и запускает
`pnpm dlx @deepseek-ai/dsh@0.2.1-alpha.2 --profile mayori`; ручной выбор
хранилища не нужен. Bundle направляет игровые данные в `~/.dsh-mayori`
через отдельный `mayoriStorage` service и Config native DSH providers.
`DSH_HOME` по-прежнему выбирает место установки профиля; сам по себе он
больше не перенаправляет игровые каталоги Mayori.

Для локальных проверок из checkout DSH используйте отдельный временный
Harness home и установите соседний checkout Mayori:

```powershell
$env:DSH_HOME = Join-Path $HOME '.dsh-mayori-dev'
pnpm dsh --profile mayori --from-default-profile web --dump-config
pnpm dsh plugin --profile mayori add (Join-Path (Split-Path (Get-Location) -Parent) 'Mayori')
```

Инициализация из Web-шаблона требуется один раз. Для повторной проверки
установки повторяйте только `plugin add`. Затем в тестовом
`$DSH_HOME/profiles/mayori/cordis.patch.yml` обязательно переопределите
корень Mayori, чтобы smoke не затрагивал пользовательский `~/.dsh-mayori`:

```yaml
- id: mayori-storage
  config:
    root: !!js dshHomePath('mayori-data')
```

Пути session persistence, storage-json, credentials, attachments и игровых
каталогов должны разрешиться в этот тестовый root. Bundle по умолчанию
использует порт `3081`, сохраняя явный `--port`; для smoke задавайте свободный
порт в команде. Проверьте dump и запустите Host:

```powershell
pnpm dsh --profile mayori --dump-config
pnpm dsh --profile mayori --no-open --port 3094
```

В dump должны присутствовать `mayori-storage`, required inject `mayoriStorage`
у потребителей хранилища, пустой `system-prompt.personaPrefix`, один агентный
`preset-mayori` с изолированным group, `dsh-mayori/optional-plugins`,
`mayori-plugin-settings`, director и пути каталогов, включая `presetsPath`.
Игровых инструкций в агентном пресете быть не должно. Проверьте переключатели
существующего чата, перезапуск и чтение сохранённого броска.
[Руководства по пресетам](presets.md) и [плагинам](plugins.md).

Для проверки опубликованного DSH вместо source launcher используйте
`pnpm dlx @deepseek-ai/dsh@0.2.1-alpha.2`. Каждая проверка использует отдельный
`DSH_HOME` **и** тестовый `mayori-storage.root`. Реальный профиль игрока
для smoke не переустанавливается.

При проверке системной инструкции убедитесь, что `system-prompt` отключает
`includeHarnessIdentity` и `includeRuntimeContext`, `web-runtime` отключает
`surfaceContext`, `tools` использует `mode: native`, а `ui-deliverables`
отключён. Web runtime сохраняет `openBrowser`, `printUrl`, `publicUrl` и
`trustedHosts`. Keyless smoke подтверждает agency, карточку, отсутствие
coding tools и необязательных технических snapshots. Обязательный
`working-directory:current` сохраняется в session log.

### Keyless smoke

`node scripts/browser-chat-commands-smoke.js <URL-test-Host>` проверяет `/preset`, `/persona` и `/new` в настоящем composer изолированного профиля с probe: поиск, текущий выбор, Enter/Tab, Escape и возврат фокуса, ширину 320 px, отключение пресета, возврат к имени `Игрок`, создание отдельного чата с тем же персонажем и default-пресетом, сохранность исходного журнала и отсутствие модельных запросов. Сценарий создаёт тестовые чаты и временные записи каталогов, удаляя пресет и персону после проверки.

`node scripts/presets-smoke.js http://127.0.0.1:3094` проверяет библиотеку игровых пресетов, новый default, применение, модельный system prompt, буквальные макросы, удаление, отключение и fork из старого префикса. Он также редактирует приветствие и его ручную ветку после удаления пресета, проверяет сохранённые инструкции и явный режим без пресета при другом default. `node scripts/browser-presets-smoke.js <URL-test-Host> <output-directory>` проверяет создание и выбор через UI, сохранение и явное применение, дублирование, удаление, сохранность новых и существующих черновиков при переходах между панелями, клавиатуру и reflow на 320 px. Оба сценария требуют временный профиль с probe.

В изолированном профиле добавьте тестовый overlay (не в профиль игрока):

```yaml
- id: session-telemetry-otel
  disabled: true
- insert:
    - id: mayori-smoke-probe
      name: C:/pet_projects/Mayori/scripts/dsh-smoke-probe.js
```

После установки checkout и сборки browser half запустите `pnpm dlx @deepseek-ai/dsh@0.2.1-alpha.2 --patch <absolute-smoke-overlay.yml> --profile mayori --no-open --port 3090`. Launcher-параметры, включая `--patch`, должны находиться перед app-параметрами `--no-open` / `--port`.

`node scripts/plugin-settings-smoke.js http://127.0.0.1:3090` проверяет все восемь сочетаний переключателей в одном уже начатом чате реального тестового Host: фактические schemas игровых запросов, одинаковые системные инструкции, изоляцию от root и чтение старого результата без повторного броска. Выбор восстанавливается в finally. `browser-plugin-settings-smoke.js` проверяет страницу, клавиатуру, размеры и сохранение через UI. Используйте только временный профиль с probe.

`node scripts/smoke-dsh.js http://127.0.0.1:3090` импортирует карточку, создаёт RPG-сессию, сохраняет выбор, удаляет исходную карточку и проводит ход через тестовый LLM provider. Базовый пресет проверяется без вызовов игровых tools. При выборе Dice/Rules проверяются только доступные инструменты, полный trace и его чтение/форк. Для другого default задайте `MAYORI_SMOKE_PRESET` ожидаемым ID. Скрипт печатает sessionId; после остановки и повторного запуска Host выполните его с `<sessionId>` для продолжения и чтения исходного trace, если History подключён. Probe не входит в опубликованный пакет, использует локальный тестовый origin и не обращается к реальному LLM API.

Dice tests проверяют изоляцию ошибок полей, сравнения и строгие boolean-типы, count, цепочки взрывов/перебросов и их лимиты, выбор kh/kl, ленивые if/and/or, прямые и обратные ссылки, циклы, глубину зависимостей и отсутствие повторных бросков. Тестовые грани задаются provider явно; production использует node:crypto.randomInt. Replay проверяет версии 3/2/1/unversioned, compact/full content, metadata, повреждённые записи и восстановление без provider. Plugin tests проверяют независимое подключение/выгрузку, Dice без модельного consumer и реакцию Rules на отсутствие зависимости. Browser tests проверяют сохранённые boolean/ошибки/цепочки/ветки и прежние состояния карточки. При включённом Dice keyless smoke вызывает оба режима с частично ошибочным batch, проверяет точный input следующего шага модели и сохранение trace. Все механики и ограничения описаны в [dice guide](dice.md). В Web проверьте раскрытие с клавиатуры, Inspect, длинные группы, узкий экран и обе темы.

`browser-home-smoke.js` дополнительно имитирует отказ initial load галереи: проверяет явную кнопку **Повторить загрузку** с клавиатуры и автоматический повтор после перехода в другую панель и обратно. Client unit tests проверяют общий initial request для подписчиков, ошибки повтора и защиту от запоздалых ответов.

Карточка smoke test содержит `{{char}}` в разных регистрах и модельных полях, `{{user}}`, неизвестные и вложенные макросы, команды состояния/случайности, ошибочные группы и совпадения с переменными DSH (`cwd`, `model`). Скрипт создаёт default-персону Alex, проверяет оба имени в приветствии и model context, свайп в другую сторону и обратно, закрепление персоны и независимость чата от удаления каталога. После первого хода Host должен отказать в свайпе. Запрос модели и session log содержат только выбранное начало и описание игрока, без служебной подписи. Продолжение после перезапуска проверяется тем же sessionId. Unit tests используют renderer опубликованного `@deepseek-ai/dsh-system-prompt`, а не копию его логики, и проверяют teardown переменной вместе с контекстом.

Launcher поддерживает произвольные профили через `--profile`. Алиас `dsh web`
встроен в DSH отдельно; установка bundle сама по себе не добавляет формы
`dsh mayori` или `npx @deepseek-ai/dsh mayori`.

Не устанавливайте Mayori через `--profile web`: её browser half содержит
root-scoped branding и gallery contributions, поэтому такая установка намеренно
изменит обычный Web UI. Для очистки ошибочной установки используйте
`pnpm dsh plugin --profile web remove dsh-mayori`.

### Проверка редактирования и повтора ответа

`node scripts/browser-message-edits-smoke.js <URL-test-Host> <output-directory>` проверяет оба действия редактора, сохранение ответа и ввода в том же чате через кнопку и Ctrl+Enter, отсутствие новых веток, ходов и запросов к модели, неизменность исходных записей, приветствие, reload, тултипы при наведении и фокусе и редактор на 320 px. После перезапуска того же изолированного Host повторите команду с `--restore`: исправления должны восстановиться из журнала и попасть в следующий настоящий запрос. Все кастомные кнопки-иконки чата используют общий `IconButton` со штатным `Tooltip` и доступным именем; проверяйте это при добавлении новых действий.

`node scripts/browser-revisions-smoke.js <URL-из-вывода-test-Host> <output-directory>` работает только с отдельным DSH home и `dsh-smoke-probe`. Сценарий проверяет иконки рядом со штатными Copy/branch, подписи для screen reader и hover-подсказки, геометрию общей панели в обеих темах на 1280/390/320 px, отмену и возврат фокуса, пустой текст, Ctrl+Enter, редактор на узком экране, ручную реплику и приветствие без запроса к модели, изменённый ввод игрока и повтор ответа с реальными новыми tool calls. Сравнивает исходный журнал до/после, наследование персоны, фактический следующий запрос после ручного ответа и переключение веток. Фикстуры сохраняются в `fixture.json` вне пользовательского профиля.

Перезапустите тот же тестовый Host и запустите `node scripts/browser-revisions-smoke.js <новый-URL> <тот-же-output-directory> --restore`. Проверка восстанавливает холодные ветки, текст, инструменты, navigation и reload; продолжает ручную реплику и приветствие настоящим запросом, проверяет сохранённый контекст и уникальность номеров ходов. Изменение Host composition требует установки checkout в отдельный профиль и `--dump-config`: Mayori director/preset и стандартный Session Controller должны остаться подключёнными. Реальный профиль игрока не переустанавливается. Семантика описана в [руководстве по сообщениям](messages.md).

## Добавление функции

1. Определите владельца данных и события, которые переживают перезапуск.
2. Выберите существующую точку расширения DSH.
3. Для новой заменяемой возможности спроектируйте Service Definition, Provider и Consumer вместе.
4. Зарегистрируйте listeners, prompt sections и tools через `ctx` для автоматического teardown.
5. Добавьте unit test, собранный keyless сценарий и документацию пользовательского поведения.
6. Если новые данные видит модель, обеспечьте их реконструкцию из session log.

## Конфигурация

Deployment-варианты объявляются в экспортируемой Schemastery `Config`. Некорректная самодостаточная конфигурация должна останавливать загрузку с понятной ошибкой. Не прячьте изменяемые настройки в константах внутри `apply()`.

## Публикация

Перед commit выполните `pnpm run check` и smoke test `--dump-config`. При установке из GitHub рекомендуется закреплять полный commit SHA. Если проект перейдёт на TypeScript build, пакет должен либо публиковать готовый `lib/`, либо иметь self-contained `prepare` и явно документировать pnpm `allowBuilds`.

### Проверка навигации и истории

Откройте все четыре вкладки в раскрытой и свёрнутой боковой панели: кнопки, подсказки и выбранное состояние рисует DSH. В галерее проверьте импорт, фильтры, dialog карточки и `Играть`. В истории найдите чат по части названия или ID, откройте его и убедитесь, что продолжается та же сессия. Проверьте одинаковые имена с разными датами, обычный форк, пустой поиск и повторную загрузку после ошибки. Перезагрузка страницы и Host должны сохранять старые чаты; дерево директорий не появляется. `pnpm run check` покрывает catalog membership, фильтрацию, сортировку, подписки и регистрацию всех четырёх native panel entries.

Для архива проверьте отмену подтверждения, архивирование обычного и текущего чата, фильтр `Архив`, поиск внутри архива и восстановление. Архивированный чат должен оставаться в архиве после перезагрузки. Ошибка сети не должна скрывать строку, а выполняющий работу чат должен получать отказ без остановки. Unit tests проверяют Host archive membership, восстановление, подписки и передачу ошибок штатного API.

### Приветствия персонажей

Проверьте запуск с основным приветствием и пустым `first_mes`, затем выбор альтернативы в чате. В компактных карточках нет выбора начала и preview; окно информации сохраняет их вместе с кнопкой «Играть». Проверьте выбор альтернативы для пустого основного приветствия; Host API альтернативного запуска остаётся совместимым. Первое сообщение должно появляться до ввода игрока. Повторное открытие, перезапуск Host и форк не должны дублировать приветствие. Unit tests покрывают выбор, недопустимые индексы, формирование закрытого начального хода, освобождение AgentHandle при ошибке flush и совместимость старых snapshots. Keyless smoke проверяет assistant-role приветствие до первого LLM-вызова и наличие ровно одного приветствия в последующей истории, включая продолжение после перезапуска. Невыбранные альтернативы не должны попадать в модельный контекст.

Для отдельной проверки альтернативного начала выполните `node scripts/smoke-dsh.js http://127.0.0.1:3090 --alternate`; при повторном запуске с выведенным sessionId также передайте `--alternate`.

### Проверка Trajectory

Тестовый adapter в `scripts/dsh-smoke-probe.js` объявляет `systemPromptUpdate: in-history`, как настоящий capable provider. `scripts/smoke-dsh.js` должен проверять первый элемент фактического input, а не визуальное положение SYSTEM: роль system, инструкции перед карточкой, карточка ровно одна. Проверьте основной/альтернативный opening, повторный ход и resume: ни system prompt, ни карточка не должны дописываться после приветствия. Старый выбранный запрос остаётся неизменяемым: исправленный порядок проверяется в новом запросе после перезапуска Host.

После холодного boot и reload вкладка чата должна идти первой, перед Trajectory. В SYSTEM выбранного нового запроса проверьте порядок: инструкции ведущего, `<mayori-character-card>`, затем переписка в остальных строках. Контекст карточки должен встречаться в input ровно один раз. Старые запросы сохраняют свой прежний input. При загрузке старой сессии прежняя секция Mayori в runtime context заменяется logged записью без карточки; соседние runtime sections сохраняются. Проверьте повторное открытие, смену персоны и форк: миграция не дублируется и не меняет исторические запросы.

В Trajectory по умолчанию выбран «Контекст запроса». До первого обращения к модели показывается текущий сохранённый контекст. Несколько раз переключите приветствие, отправьте сообщение и проверьте: остаётся только выбранное начало и ввод игрока, ответ на этот запрос исключён. Переключение на текущий сохранённый контекст добавляет ответ. В следующем ходе выберите предыдущий запрос: поздние сообщения и замены не должны менять его вход. После компактации старый запрос сохраняет исходный контекст, новый использует summary.

Оба режима должны иметь одну stock таблицу Trajectory с поиском, таймлайном, раскрытием записей и изображениями. В «Контексте запроса» нажмите SYSTEM: native panel должна показывать System Prompt и Tools выбранного запроса. Откройте CONTEXT и USER, проверьте полный текст и поиск. В «Текущем сохранённом контексте» появляется строка последнего ASSISTANT, а в input выбранного запроса её нет. «Полный журнал» возвращает исходные строки, включая предыдущие свайпы. Инспекция tool call открывает этот режим. Проверьте reload, холодный boot, клавиатурный выбор запросов, ширину 390 px и сеть: ошибка не должна выдавать прошлый input за выбранный. `scripts/smoke-dsh.js` сравнивает восстановленный input с точными сообщениями, полученными adapter, а текущий snapshot — с `session.deriveMessages()`.

### Персоны и переключение начала

При проверке аватаров сравните границы `.mayori-message-content` с границами всей строки: они должны совпадать и для персонажа, и для игрока. На широком экране аватары занимают боковые поля с зазором 12 px; при недостатке места переходят над сообщением с зазором 8 px, оставляя всю ширину тексту. Измените ширину окна, колонки чата и состояние sidebar без перезагрузки. `browser-smoke.js` проверяет эту геометрию в обеих темах на 1280/390/320 px вместе с доступностью окна аватара, сохраняя ещё шесть screenshots чата без dialog (18 всего).

Регрессия окна аватара проверяется `node scripts/browser-smoke.js <URL-из-вывода-test-Host> [output-directory]` только на изолированном Host с probe. Нужны Playwright и установленный Chromium; `MAYORI_PLAYWRIGHT_PATH` позволяет указать путь к пакету, `MAYORI_CHROMIUM_PATH` — к браузеру. Скрипт создаёт настоящий PNG 256×1024 для персонажа и 768×256 для персоны, проводит keyless ход, затем проверяет opaque background, portal в body, положение картинки под заголовком, отсутствие overflow, клавиатуру, backdrop и возврат фокуса. Светлая/тёмная темы и ширины 1280/390/320 px дают 12 screenshots для visual QA. Probe выдаёт мысли перед tool call и перед текстом ответа: проверьте ровно один аватар у приветствия и один у ответа, без повторов в reasoning-part или tool-only шагах, включая reload. Аватар должен быть соседним элементом снаружи блока содержимого; пустые ответы не оставляют аватар и пустую колонку. Unit tests также покрывают running/settled/interrupted, несгруппированный ответ и ответ только с изображением. Отсутствие probe останавливает сценарий до изменения default-персоны или импорта карточки.

В чате с PNG-карточкой и персоной с аватаром проверьте каждое сообщение: изображение персонажа слева, игрока справа. Проверьте приветствие, обычные ответы, streaming, steering и вложения штатных сообщений. Клик и Enter/Space открывают изображение целиком; Escape, кнопка закрытия и backdrop закрывают окно и возвращают фокус на аватар. Проверьте Tab внутри dialog, светлую/тёмную тему, 320/390 px и 200% zoom. Карточка JSON без картинки и персона без аватара показывают начальную букву имени. Ошибка загрузки картинки также даёт этот fallback. Аватар PNG сохраняется в snapshot чата и наследуется при форке; удалите исходную карточку и перезапустите Host. Старые snapshots получают картинку из ещё доступного каталога при первом восстановлении; если карточка уже удалена, используется буква имени. Изображения не должны попадать в модельный prompt.

После установки checkout в новый временный профиль проверьте `--dump-config`: `mayori-director.config.personasPath` должен указывать на его собственный `~/.dsh-mayori/mayori/personas`. Вкладка `Персоны` работает без активного чата. Создайте имя и описание с `{{user}}`, загрузите аватар, сохраните и выберите default. В preview окна информации персонажа и новом чате должны отображаться подставленные имена. В редакторе сохраняется исходный текст шаблонов.

В чате до ввода проверьте переход вперёд/назад, циклический переход с последнего варианта на первый, пустую альтернативу, Copy и reload. Затем закрепите другую персону через её вкладку и вернитесь в чат: приветствие должно обновиться. После первого хода свайпы исчезают; прямой Host вызов `swipe` должен отказать. Проверьте неизменность прошлых сообщений при последующей смене персоны, restart, удаление записи каталога и создание ветки после свайпа. Новая ветка должна сохранять выбранное начало. Компактация модельного контекста не должна менять отображаемое приветствие.

Для UI QA проверьте светлую/тёмную тему, клавиатуру, названия кнопок, загрузку/ошибку, поля без имени, отклонённые avatar SVG/файлы больше 2 МБ, ширины 390 и 320 px без горизонтального overflow. Browser module ожидает стандартные `assistant-step` и `turn-tail` через публичный `slots.subscribe`; тестируйте холодный boot, когда slot уже объявлен, но штатный renderer ещё не зарегистрирован. `pnpm run check` дополнительно покрывает default persistence, независимость chat snapshot, безопасный template renderer и Host ограничения свайпов.

### Главная, превью истории и страницы каталога

На пустом профиле проверьте приветствие и пустые состояния главной, переходы в историю и персонажи. После импорта и создания больше пяти чатов главная показывает ровно пять последних неархивных сессий и пять последних импортированных карточек. Клик по бренду Mayori Engine и Enter/Space на его кнопке возвращают главную из чата, галереи, истории и персон без создания пустого чата; именованный чат без приветствия сохраняет поле ввода. Открытие строки восстанавливает ту же сессию. В истории проверьте аватар из snapshot после удаления исходной карточки, сокращённое сообщение, букву при отсутствии картинки, archive, fork и cold read после перезапуска. Ошибка preview одной строки не скрывает другие чаты и не блокирует открытие.

В каталоге проверьте правую панель фильтров, 3/5/7 колонок и сохранение после reload, 20/40/60 карточек на страницу, последнюю неполную страницу и возврат на первую после фильтра или смены лимита. На ширинах 1600/1280/390/320 px и в светлой/тёмной теме сетка не должна обрезать кнопки; drawer фильтров открывается справа. Keyboard focus остаётся видимым.

`node scripts/browser-home-smoke.js <URL-из-вывода-test-Host> [output-directory]` запускается только с изолированным smoke probe. Скрипт импортирует 45 карточек, создаёт тестовые сессии, проверяет последние пять записей, preview, переходы, страницы, фильтры, сохранение preferences, возврат по бренду, отсутствие New Session в обеих ширинах sidebar и отсутствие clipping; сохраняет 16 screenshots. Использует те же `MAYORI_PLAYWRIGHT_PATH` и `MAYORI_CHROMIUM_PATH`, что avatar smoke. Unit tests покрывают preferences, границы страниц, immutable сортировку последних карточек, восстановление превью из логов и изоляцию отказов cold reads. Новый Host-файл включён в package files.

Rules tests проверяют натуральную 1 при итоговых 7, криты выбранной грани при преимуществе/помехе, дополнительный урон без повторного модификатора, отсутствие бросков урона при провале, реальные броски таблиц последствий, preflight и сохранение проверок при runtime errors. Session tests восстанавливают compact/full results без новых бросков; client tests проверяют видимые исходы, последствия, native disclosure и raw fallback. В [rules guide](rules.md) описаны профили и Config. При ручной Web проверке проверьте крит/провал без раскрытия, keyboard toggle, узкий экран и обе темы.

`node scripts/browser-rules-smoke.js <local-url> <sessionId> <output-directory>` проверяет записанный `resolveCheck` в отдельном Host с тестовым probe: выбранную грань и итог, клавиатурное раскрытие, отсутствие переполнения при ширине 1280/390/320 и обе темы. Для внешнего Playwright используйте `MAYORI_PLAYWRIGHT_PATH`, для установленного Chromium — `MAYORI_CHROMIUM_PATH`. Скрипт читает запись и не вызывает новых бросков.
