# Производительность каталогов и изображений

Mayori загружает метаданные видимых карточек и превью видимых чатов. Полная карточка читается по ID при открытии информации или выборе персонажа. Оригиналы портретов передаются при раскрытии изображения. Источниками данных остаются JSON-карточки, сохранённые snapshots и штатные журналы DSH.

## Каталог персонажей

`CharacterLibraryService.query()` и POST `/mayori/characters/list` принимают `page`, `pageSize` (1–60), `query`, `sort` (`newest`, `name`, `creator`), `creator`, `tags` и `portrait` (`all`, `with`, `without`). Ответ содержит `cards`, `total`, `filteredTotal`, фактическую страницу, `facets`, `indexing` и `unavailable`. Карточки списка содержат только ID, имя, дату импорта, автора, теги и локальный URL миниатюры. Поиск учитывает также description и personality, не передавая их браузеру. Полную карточку возвращают `get(id)` и POST `/mayori/characters/get` с `{ "id": "…" }`. Host API `list()` сохранён для совместимости; он читает весь каталог и не используется новым интерфейсом или запуском чата.

SQLite-индекс `charactersPath/cache/catalog-v1.sqlite` пересоздаётся из исходных JSON. Первое чтение проверяет файлы по размеру, mtime и ctime, читая содержимое только изменившихся записей. Первая порция большого индекса доступна после 60 файлов; остальная работа продолжается с уступкой event loop каждые 20 записей. Пока `indexing: true`, порядок, счётчики и фильтры могут уточняться. Подписанный browser provider повторяет запрос каждые 400 мс до завершения. Повреждённая карточка исключается отдельно и учитывается в `unavailable`.

Импорт и удаление сразу обновляют индекс. Ручное изменение файлов вне приложения обнаруживается при следующем запуске Host. Главная получает пять карточек, галерея — одну страницу 20/40/60; фильтры независимы. Поиск задерживается на 150 мс, старые запросы отменяются. Импорт читается и отправляется последовательными порциями по два файла, до 16 МиБ на файл.

## Портреты и аватары

`MediaService` (`mayoriMedia`) / `FileSystemMediaProvider` / HTTP image consumer образуют отдельную capability. `ImageStore` сохраняет исходные байты под SHA-256 в `charactersPath/media/<hash>.original`, MIME — в `<hash>.json`. Snapshot хранит ссылку `mayori-media:<hash>`. Удаление карточки или персоны не удаляет ресурс старого чата. Одинаковые изображения используют общий оригинал; библиотечный PNG нового импорта является hard link, если файловая система его поддерживает, иначе отдельной копией.

GET `/mayori/characters/media/<hash>/<variant>` отдаёт ресурс; `/mayori/characters/card-image/<cardId>/<variant>` разрешает портрет старой карточки и сохраняет маленькую побочную ссылку в `charactersPath/cache`. Варианты `avatar`, `gallery`, `preview` создаются лениво через sharp, с сохранением пропорций и без увеличения. `original` отдаёт исходные байты. ETag и private HTTP cache позволяют повторно использовать изображения. Файловая аренда освобождается после ответа, включая 304 и ошибки.

Новый импорт публикует URL с hash изображения: повторный импорт той же карточки с другим PNG сразу меняет URL портрета. Legacy `card-image` использует `private, no-cache` с ETag, поскольку ID карточки вычисляется из её JSON и может не измениться при смене картинки. Старые snapshots сохраняют свой оригинал.

Миниатюры WebP находятся в `media/cache`. При превышении лимита вытесняются производные файлы, кроме используемых текущими ответами; кеш может временно превышать лимит до окончания передачи. Оригиналы автоматически не удаляются. Резервная копия должна сохранять `media`, JSON-карточки, персоны и snapshots вместе: перенос каталога без `media` теряет ресурсы старых чатов.

Старые PNG и data URI читаются. Аватары каталога персон переводятся в ссылки при первом чтении с сериализованной записью; изображения старых snapshots — при штатном восстановлении чата. Модельные тексты и события этим не меняются. Сообщения и история используют `avatar`, галерея — `gallery`, раскрытие портрета — `original`.

## История и память браузера

DSH владеет каталогом, архивом и журналами. Превью запрашиваются только для видимых строк (до 60 ID). Host выполняет не больше `history.concurrency` чтений одновременно для всех запросов вместе, объединяет совпадающие чтения и сохраняет результат в ограниченных кешах памяти и SQLite `campaignsPath/cache/previews-v1.sqlite`.

Ключ актуальности включает native persistence revision, live sequence, fingerprint snapshot персонажа/персоны, унаследованный snapshot и message projections. Перед кешированием ключ проверяется повторно. Ошибки не кешируются. Native revisions имеют силу в пределах экземпляра сервиса: после перезапуска первое чтение каждого превью повторно проверяет журнал, затем дисковый кеш помогает при вытеснении из памяти. Превью ограничено 180 Unicode code points и строится без копирования всего длинного текста в массив символов.

Browser кеш превью ограничен 128 записями / примерно 2 МиБ строкового представления. Готовый каталог DSH не обновляется заново при каждом переходе на главную или историю. Главная выбирает пять последних строк без второго полного отсортированного массива. Неактивные session providers вытесняются после 16 чатов; trajectory providers — после четырёх, с освобождением тяжёлого результата после последней подписки. Активные подписчики сохраняют provider и могут превышать лимит. Запоздалые ответы не заменяют актуальное представление.

Первое холодное превью требует штатного `sessionQuery.readSession()` с восстановлением полного журнала и projections. Память такого чтения зависит от длины чата; лимиты кеша не являются лимитом всей памяти DSH. Каталог метаданных сессий и активная переписка остаются штатными DSH представлениями. Оптимизация не обрезает переписку или контекст модели.

## Config и обслуживание

Поля находятся в `mayori-director.config`; provider валидирует целые положительные значения и верхние границы. Пути выводятся из `charactersPath` / `campaignsPath`.

| Поле | Default | Назначение |
| --- | ---: | --- |
| `media.avatarSize` | 96 | Максимальная сторона аватара, px |
| `media.gallerySize` | 384 | Максимальная сторона миниатюры галереи, px |
| `media.previewSize` | 1024 | Максимальная сторона preview, px |
| `media.quality` | 80 | Качество WebP |
| `media.maxPixels` | 40000000 | Лимит пикселей входа sharp |
| `media.concurrency` | 2 | Одновременные преобразования |
| `media.maxQueue` | 128 | Ожидающие преобразования |
| `media.thumbnailCacheBytes` | 268435456 | Бюджет производных файлов, bytes |
| `media.maxVariantFiles` | 2048 | Число файлов производного кеша |
| `history.cacheEntries` | 128 | Превью в памяти Host |
| `history.cacheBytes` | 2097152 | Приблизительный строковый бюджет Host, bytes |
| `history.diskEntries` | 512 | Превью в SQLite |
| `history.concurrency` | 4 | Одновременные чтения журналов |
| `history.maxPending` | 128 | Ожидающие чтения |

При остановленном Host можно удалить производные каталоги `charactersPath/cache`, `media/cache`, `campaignsPath/cache`: они восстановятся. Original media, карточки, personas.json и selections не являются кешами.

## Измерения и проверки

Изображения по HTTP в размер JSON не входят. Это синтетический локальный замер, не обещание времени открытия любого чата.
